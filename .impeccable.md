# Impeccable

## Design Context

### Users

People doing fare construction. They already read `LHR-BA-JFK-AA-X/LAX-JL-NRT` without
being taught the grammar, they know what section 4(e) is, and they are checking a
specific itinerary against a specific tariff — not browsing. Travel agents, mileage-run
planners, and the author. They arrive with a routing in hand and want a verdict.

The context of use is a desk, mid-task, often with a GDS or a spreadsheet open beside
it. Sessions are short and repeated: paste, validate, adjust, validate again.

### Brand Personality

**Terse. Authoritative. Instrument-like.**

The page is an instrument that reports a reading. It does not congratulate, reassure, or
sell. It states what it checked, what it could not check, and why — the "not checked"
panel exists precisely because claiming coverage the report does not give would be a
lie, and the visual design must carry that same refusal to overstate.

Emotionally: confidence through precision. The user should trust the verdict because
the interface is visibly rigorous, not because it is friendly.

### Aesthetic Direction

A tariff manual and a departure board, not a booking site. Reference points: airline
timetables of the 1960s–70s (condensed grotesques, ruled columns, no ornament), Jeppesen
chart legends, a GDS response pane. Data is the content; chrome is overhead.

Anti-references: consumer travel UI (hero images, gradients, rounded cards floating on
grey), dashboard-template aesthetics (stat tiles, sparklines as decoration), anything
that would make a fare a "journey".

Theme: both, following `prefers-color-scheme`. Dark is not a styling flourish here —
half of this audience works in a dim room at 11pm.

Type: **Archivo** (variable, weight + width axes) for interface text, running condensed
for column headers and section labels the way a timetable does. **Martian Mono**
(variable) for every code, time, and identifier — the things the user actually reads.
Both are embedded, not fetched: the service is offline-capable by design and a font CDN
would be the only outbound request on the page.

### Design Principles

1. **Density is a feature.** This audience reads tables. Do not spend vertical space on
   breathing room they did not ask for; spend it on showing more of the itinerary at
   once.
2. **Never dress up an absence.** Indeterminate and not-checked must never read as a
   pass. Uncertainty gets its own visual register — dashed, unfilled, explicitly named.
3. **Codes are typeset, prose is set.** Anything the user would type into a GDS is
   monospace and tabular. Anything explaining a rule is proportional. The distinction is
   never blurred.
4. **The verdict is the largest thing on the page.** Everything else is evidence for it.
5. **Two ways in, one itinerary.** A routing string and a segment table are the same
   journey at different resolutions. Moving between them must never silently lose or
   invent data.
